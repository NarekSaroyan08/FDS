# FaceTracker для Raspberry Pi 4

Система слежения за лицом с двумя камерами: **неподвижная камера** находит лицо (OpenCV, каскад Хаара), а двухосевой сервоподвес (pan/tilt) поворачивает **подвижную камеру** на найденную цель. Во время обычного слежения программа читает только неподвижную камеру. Управление дополнительным DC-мотором временно отключено после сообщения о перезагрузке Raspberry Pi и неконтролируемом движении мотора. Когда лица нет, подвес ведёт поиск, двигаясь по синусоиде.

Соответствие «пиксель неподвижной камеры → углы сервоприводов подвижной камеры» задаётся **таблицей калибровки (LUT)**. При калибровке обе камеры временно подключают к Raspberry Pi: шахматная доска определяется в обоих кадрах, а углы выставляются клавишами до совмещения центра доски с центром кадра подвижной камеры.

## Структура проекта

```
FaceTracker/
├── src/
│   ├── facetracking.cpp      # детекция на неподвижной камере + PID-сервы
│   └── calibration.cpp       # калибровка LUT по двум камерам и шахматной доске
├── data/
│   ├── haarcascade_frontalface_default.xml   # модель детектора лиц OpenCV
│   ├── calibration.txt       # таблица старой однокамерной калибровки
│   └── fixed_to_servo.txt    # таблица неподвижная камера → углы подвеса
├── scripts/
│   └── setup_project.sh      # установка зависимостей на RPi4
├── build/                    # бинарники (создаются make, в git не попадают)
├── old/                      # предыдущие версии исходников (для истории, не собираются)
│   ├── src/facetracking.cpp
│   ├── src/calibration.cpp
│   └── scripts/setup_project.sh
├── Makefile                  # сборка: make / make run / make calibrate / make clean
├── .gitignore
└── README.md
```

| Файл | Назначение |
|------|-----------|
| `src/facetracking.cpp` | Два потока: **vision** (захват с неподвижной камеры, поиск лица, пересчёт в целевые углы по LUT, поиск при потере лица) и **servo** (PID-сглаживание и выдача импульсов на сервоприводы каждые 15 мс). |
| `src/calibration.cpp` | Открывает обе камеры, ищет шахматную доску и записывает пары «центр доски в неподвижной камере ↔ углы сервоприводов», когда доска находится в центре подвижной камеры. |
| `data/haarcascade_frontalface_default.xml` | Стандартный каскад Хаара из репозитория OpenCV (фронтальные лица). |
| `data/fixed_to_servo.txt` | Таблица новой калибровки. Файл старой однокамерной калибровки `data/calibration.txt` не используется. |
| `old/` | Предыдущие версии файлов. Makefile их не собирает. |
| `scripts/setup_project.sh` | Ставит OpenCV, pigpio и инструменты сборки, скачивает каскад, если его нет. |

> Все пути к данным относительные (`data/...`), поэтому **программы запускаются из корня проекта**. Пути меняются при сборке:
> `make CXXFLAGS+='-DCALIBRATION_FILE=\"/path/calib.txt\" -DCASCADE_FILE=\"/path/cascade.xml\"'`

## Оборудование и подключение

- Raspberry Pi 4 (64-битная Raspberry Pi OS, aarch64)
- Неподвижная камера, доступная через V4L2 (по умолчанию `/dev/video0`)
- Подвижная камера на сервоподвесе: при калибровке её тоже нужно временно подключить к Raspberry Pi как отдельное V4L2-устройство (по умолчанию `/dev/video2`); при слежении её видеопоток программе не нужен
- 2 сервопривода (SG90 / MG90S или аналоги): pan и tilt
- DC-мотор и двухканальный релейный модуль на показанной пользователем установке (питание мотора отключено до проверки проводки)
- Отдельный источник 5 В для сервоприводов (питание от GPIO-гребёнки Pi не подходит)

Нумерация пинов: **BCM** (как в pigpio).

| Сигнал | BCM GPIO | Физ. пин | Куда |
|--------|---------:|---------:|------|
| `SERVO_X` (pan) | 17 | 11 | сигнальный провод серво X |
| `SERVO_Y` (tilt) | 27 | 13 | сигнальный провод серво Y |
| Реле 1 (ранее управлялось программой) | 13 | 33 | вход релейного модуля; программа больше не управляет им |
| Реле 2 (ранее управлялось программой) | 5 | 29 | вход релейного модуля; программа больше не управляет им |
| GND | — | 6, 9, 14 … | **общая земля** с питанием серво и драйвером |

**DC-мотор:** питание мотора следует физически отключить до проверки релейного модуля, контактов и источника питания. При нажатии `Z/X` мотор запустился, Raspberry Pi перезагрузился, а мотор продолжил движение. На фото установлен двухканальный релейный модуль, не H-мост; его входы могут быть активными при LOW. Программная команда остановки не может сработать, если Pi потерял питание. Новая версия калибровки и трекера вообще не обращается к GPIO 13/5; трекер отклоняет `--enable-motor`. Старые бинарные файлы на Pi остаются опасными до пересборки. Удаление команд из программы не гарантирует выключения реле во время загрузки или перезагрузки Pi.

## Установка

На Raspberry Pi:

```bash
git clone <repo-url> FaceTracker      # или скопируйте папку проекта
cd FaceTracker
chmod +x scripts/setup_project.sh
./scripts/setup_project.sh
```

Скрипт:
1. обновляет систему и ставит `build-essential`, `cmake`, `pkg-config`, `git`, библиотеки кодеков и GTK;
2. ставит `pigpio` и **выключает демон `pigpiod`**: программы используют библиотеку pigpio напрямую (`gpioInitialise()`), а она не работает, пока GPIO занят демоном;
3. ставит `libopencv-dev` (OpenCV 4);
4. скачивает `data/haarcascade_frontalface_default.xml`, если его нет, и создаёт пустой `data/fixed_to_servo.txt`.

## Сборка

```bash
make            # собирает build/facetracking и build/calibration
make clean      # удаляет бинарники
```

Без Makefile:

```bash
mkdir -p build
g++ -O2 -std=c++17 -o build/facetracking src/facetracking.cpp `pkg-config --cflags --libs opencv4` -lpigpio -lpthread -lrt
g++ -O2 -std=c++17 -o build/calibration  src/calibration.cpp  `pkg-config --cflags --libs opencv4` -lpigpio -lpthread -lrt
```

Нужен C++17 (`std::clamp`). Обе программы открывают окно OpenCV (`imshow`), поэтому нужен рабочий стол или X-forwarding (`ssh -X`).

## Калибровка

Калибровку делают после сборки подвеса и повторяют при изменении положения любой камеры или механики подвеса. Временно подключите **обе** камеры к Raspberry Pi. Установите плоскую шахматную доску так, чтобы её целиком видели обе камеры. Для доски с фото, подписанной «8×12 | Checker Size: 21 mm», программа по умолчанию ожидает **12 клеток по горизонтали и 8 по вертикали**, то есть **11×7 внутренних углов** OpenCV. Если нужна другая распечатка, [шаблон A4](output/pdf/facetracker_chessboard_8x12_21mm_A4.pdf) имеет те же размеры: печатайте в масштабе 100% без подгонки страницы; клетка — 21 мм, всё поле — 252×168 мм, контрольная линия — 100 мм. Доску держите плоской и без бликов: складки и отражения на прозрачной обложке мешают распознаванию углов.

```bash
make calibrate          # = sudo ./build/calibration
```

По умолчанию неподвижная камера использует `/dev/video0`, а подвижная — `/dev/video2`. Для подвижной камеры программа запрашивает MJPEG, 640×480, 15 кадров/с. Этот режим проверен отдельно на камере `/dev/video2`; работу двух камер одновременно нужно проверить на Raspberry Pi.

Если камеры имеют другие номера или у доски другое число внутренних углов, запустите собранную программу с аргументами «устройство неподвижной камеры, устройство подвижной камеры, углы по горизонтали, углы по вертикали». Например, для устройств `/dev/video0` и `/dev/video2` и доски с 9×6 внутренними углами:

```bash
make build/calibration
sudo ./build/calibration /dev/video0 /dev/video2 9 6
```

Проверить номера камер можно командами `ls -l /dev/video*` и `v4l2-ctl --list-devices` (пакет `v4l-utils`). Числа `0 2` тоже допускаются вместо путей. Выбирайте именно узлы видеозахвата двух разных камер: `/dev/video1` может быть служебным узлом первой камеры. Если используется CSI-камера Raspberry Pi с `libcamera`, проверьте её отдельно командой `rpicam-hello --list-cameras`: номера из этого списка **не равны автоматически** номерам `/dev/video*`, которые открывает текущая программа через V4L2.

Управление (фокус должен быть на одном из окон OpenCV):

| Клавиша | Действие |
|---------|----------|
| `A` / `D` | серво X −2° / +2° |
| `W` / `S` | серво Y −2° / +2° |
| `Space` | записать точку, только когда доска стабильна в неподвижной камере и центрирована в подвижной |
| `P` | сохранить все точки в `data/fixed_to_servo.txt` (файл **перезаписывается**) |
| `C` | очистить LUT **и** файл `fixed_to_servo.txt` |
| `Q` | выход |

Порядок работы:
1. Покажите доску обеим камерам. На экране откроются два окна: `Fixed camera` и `Moving camera`. Если нужен новый набор точек, нажмите `C` (эта клавиша сразу очищает файл).
2. Перемещайте доску в разные места поля зрения **неподвижной** камеры. Клавишами `A/D/W/S` поверните подвес так, чтобы цветная точка центра доски в окне **подвижной** камеры совпала с жёлтым крестом в центре изображения. `Z/X` не управляют DC-мотором.
3. Дождитесь надписи `Ready - SPACE to record` в окне неподвижной камеры и нажмите `Space`. Требуются стабильная доска в обоих кадрах и отклонение не более 20 px от центра подвижной камеры. Точка не запишется, если её положение в неподвижном кадре ближе ±20 px к уже существующей точке.
4. Повторите для разных зон кадра. Рекомендуется 15–30 точек, включая края и углы. Держите доску на типичных рабочих расстояниях: из-за разнесения камер соответствие меняется с расстоянием до цели.
5. Нажмите `P`, чтобы сохранить, затем `Q`.

При старте программа подгружает уже существующие точки из `data/fixed_to_servo.txt`, так что калибровку можно дополнять. Перед выходом не забудьте нажать `P`. После записи таблицы подвижную камеру можно отключить от программы: трекер читает только неподвижную.

Таблица калибровки хранит только положение доски в неподвижной камере и углы двух сервоприводов; положение DC-мотора в ней не сохраняется.

## Запуск трекинга

```bash
make run                # = sudo ./build/facetracking
```

Если неподвижная камера имеет другой номер, запустите `sudo ./build/facetracking /dev/video2` (число `2` тоже допускается). Флаг `--enable-motor` пока отклоняется программой.

В окне трекера строка `Motor preview` показывает расчёт по **неподвижной** камере: лицо выше центральной полосы ±30 px — `UP`, ниже — `DOWN`, внутри полосы или при отсутствии лица — `STOP`. Это только предварительный просмотр: реле и DC-мотор не включаются. Питание мотора оставляйте отключённым до проверки силовой схемы и причин перезагрузки Pi.

- `sudo` обязателен: pigpio работает с DMA и регистрами GPIO напрямую.
- Окно «PRO Tracker» показывает кадр **неподвижной** камеры с зелёной точкой в центре найденного лица.
- `Q` в окне завершает программу. Сервоприводы отключаются, pigpio корректно закрывается; питание DC-мотора остаётся физически отключённым.

## Клавиши управления

Клавиши работают, когда фокус находится на окне OpenCV.

| Программа | Клавиша | Действие |
|-----------|---------|----------|
| `facetracking` | `Q` | выход (серво отключаются; GPIO 13/5 не используются) |
| `calibration` | `A` / `D` | серво X −2° / +2° |
| `calibration` | `W` / `S` | серво Y −2° / +2° |
| `calibration` | `Space` | записать точку LUT после совмещения центра доски в подвижной камере |
| `calibration` | `P` | сохранить LUT в `data/fixed_to_servo.txt` |
| `calibration` | `C` | очистить LUT и файл |
| `calibration` | `Q` | выход без автосохранения |

## Как это работает

```
 неподвижная камера ──► [vision thread] ───────────────────► [servo thread] ──► GPIO 17/27 ──► подвижная камера
             640×480 → gray → ×0.5                              PID X/Y
             detectMultiScale (Haar)                            clamp 20..160°
             лицо найдено?                                      pulse = 1000 + angle·5 µs
               да:  центр (fx,fy) → прогноз → LUT (IDW, k=5) ─► servoX/servoY (atomic)
               нет: синусоидальный поиск ───────────────────► servoX/servoY
```

1. **Захват и детекция.** Кадр 640×480 переводится в оттенки серого и уменьшается вдвое (320×240), это ускоряет `detectMultiScale(scale=1.2, minNeighbors=3)`. Берётся первое найденное лицо, его центр пересчитывается обратно в координаты 640×480.
2. **Прогноз.** Целевая точка смещается вперёд на половину межкадрового сдвига: `pred = f + 0.5·(f − f_prev)`. Это компенсирует задержку.
3. **LUT-интерполяция.** Для точки `pred` ищутся 5 ближайших точек калибровки и усредняются с весами `w = 1/(d+1)²` (inverse distance weighting). Получаются целевые углы `servoX/servoY`.
4. **Поиск.** Если лица нет, цели меняются по `X = 90 + 40·sin(t)`, `Y = 90 + 20·cos(0.7t)`, где `t` растёт на 0,03 за кадр.
5. **Servo-поток (≈66 Гц).** PID (`kp=0.12, ki=0.0001, kd=0.08`) плавно ведёт выходной угол к цели. Угол ограничивается 20…160° и переводится в импульс `1000 + angle·5` мкс (1100…1800 мкс).

Потоки обмениваются данными через `std::atomic<int> servoX/servoY` и флаг `running`.

## Параметры и настройка

Все параметры заданы константами в исходниках:

| Параметр | Где | Значение | Смысл |
|----------|-----|----------|-------|
| `SERVO_X`, `SERVO_Y` | оба файла | 17, 27 | пины сервоприводов |
| Входы релейного модуля | вне программы | 13, 5 | управление временно отключено в коде |
| Разрешение / FPS | оба файла | 640×480 / 30 | `cap.set(...)` |
| `detectMultiScale` | facetracking.cpp | 1.2, 3 | масштаб шага, минимум соседей |
| Шахматная доска | calibration.cpp | 11×7 внутренних углов | размер можно задать аргументами запуска |
| `PID pidX/pidY` | facetracking.cpp | 0.12 / 0.0001 / 0.08 | kp / ki / kd |
| Диапазон углов | оба файла | 20…160° | механическая защита |
| Формула импульса | оба файла | `1000 + angle·5` мкс | подстройте под свои серво |
| `k` в LUT | facetracking.cpp | 5 | число соседей для интерполяции |
| Коэф. прогноза | facetracking.cpp | 0.5 | 0 отключает прогноз |
| Амплитуды поиска | facetracking.cpp | 40° / 20° | |

Советы по PID: если подвес дрожит, уменьшите `kp` или увеличьте `kd`. Если подвес догоняет лицо медленно, увеличьте `kp`. `ki` держите около нуля, потому что интеграл не ограничен и накапливается.

## Формат fixed_to_servo.txt

Текстовый файл. Каждая строка описывает одну точку из четырёх целых чисел через пробел:

```
<px> <py> <servoX> <servoY>
```

- `px`, `py` — положение центра доски в кадре неподвижной камеры 640×480;
- `servoX`, `servoY` — углы сервоприводов в градусах (20…160).

Пример:

```
320 240 90 90
80 60 130 70
560 420 50 112
```

## Диагностика проблем

| Сообщение / симптом | Причина и решение |
|--------------------|-------------------|
| `pigpio init failed` / `pigpio failed` | Нет `sudo` или запущен демон: `sudo systemctl stop pigpiod`. |
| `Cannot open ... camera` | Проверьте пути устройств через `v4l2-ctl --list-devices` и передайте их явно. Калибровке нужны два доступных узла видеозахвата; слежению — только неподвижная камера. Для CSI-камеры сначала проверьте `rpicam-hello --list-cameras`: её наличие там не гарантирует возможность открыть тот же номер как V4L2-видеозахват. |
| `Cascade load failed` | Нет `data/haarcascade_frontalface_default.xml` или запуск не из корня проекта. |
| `No fixed_to_servo.txt found` / LUT пуст | Не выполнена новая калибровка `data/fixed_to_servo.txt`: трекер не запустится, сначала выполните `make calibrate`. |
| Окно не открывается (`cannot open display`) | Запустите на рабочем столе Pi или через `ssh -X`. |
| Серво дёргаются / Pi перезагружается | Сервоприводы питаются от 5 В Pi. Нужен отдельный источник и общая земля. |

## Известные ограничения

- `cv::imshow`/`waitKey` в трекере вызываются не из главного потока. В некоторых сборках OpenCV это может зависнуть.
- LUT хранит только координаты пикселей, без расстояния до цели. Если неподвижная и подвижная камеры разнесены, точность наведения может ухудшаться на расстояниях, отличных от использованных при калибровке.
- При нескольких лицах отслеживается первое найденное, и оно может «перескакивать».
- Интегральная составляющая PID не ограничена (нет anti-windup).
- Угол 90° соответствует импульсу 1450 мкс, а не стандартному центру 1500 мкс. При старте серво ставятся в 1500 мкс, поэтому возможен небольшой рывок.
- В calibration клавиша `P` подписана в справке как «Append», хотя файл перезаписывается всеми точками из памяти. Данные при этом не теряются, потому что старые точки загружаются при старте.

## Старые версии (old/)

В `old/` лежат предыдущие версии файлов, которые раньше находились в корне проекта. Их сохранили для истории. Они **не собираются** и не рекомендуются к запуску. Основные отличия от текущих `src/`:

- импульс серво `500 + angle·11` мкс при диапазоне 0…180° (без защитных ограничений 20…160°);
- при потере лица подвес возвращается в центр (90°/90°), а не ищет лицо по синусоиде;
- `calibration` открывает камеру `/dev/video2` и ищет лицо в полноразмерном кадре, без сетки, без проверки «слишком близко» и без клавиши `C`;
- файлы `calibration.txt` и каскад ищутся в текущей папке, а не в `data/`;
- нет проверок ошибок загрузки каскада и камеры, нет `gpioSetMode` для пинов мотора;
- старый `setup_project.sh` включает демон `pigpiod`, хотя он мешает `gpioInitialise()`, и печатает устаревшую команду сборки `FaceTracker.cpp`.
